# 実機録音用MDX（OPM出力タイミングの校正）

mdx/ の7ファイルは生成済みです。PDX不要、非圧縮、有限長、ループなし。
先頭・末尾に約1秒の待ちがあります。原則として1つのFMチャンネルのみ発音します。
GMC-OPT04経由で前回と同じ24bit/96kHzのステレオ録音をお願いします。

## 録音の優先順

まず01SOLO・02LIVE・03CHSCANを推奨します。合計約172秒（4MHzの場合）。
05SINEはFMの側帯波が重ならない対照条件なので、その次に有用です。
余裕があれば残りも録音してください。

|MDX|4MHz時の長さ|内容|
|---|---:|---|
|01SOLO.MDX|約21秒|ch0、診断音色の全キャリア→M2単独→C1単独→C2単独。各区間で再キーオン|
|02LIVE.MDX|約31秒|ch0、発音継続のまま全→M2→全→C1→全→C2→全。TLのみ変更|
|03CHSCAN.MDX|約120秒|ch0〜7の順。各chで全→M2→C1→C2を新規発音|
|04PITCH.MDX|約61秒|ch0、KC=38h/48h/58h/68h。各音程で全→M2→C1→C2|
|05SINE.MDX|約120秒|ALG7/FB0の純音対照。ch0〜7、各chでM1/M2/C1/C2単独|
|06PAIR.MDX|約40秒|全・M2+C1・M2+C2・C1+C2。元のDT1と全DT1=0を比較|
|07LOAD.MDX|約19秒|ch0継続。他ch停止→発音中だがpan無効→他chも可聴→pan無効|

秒数はOPMマスタークロック4MHz、MDX @t=224（Timer B周期32768クロック）を仮定。
実際の開始時刻はプレーヤーの起動待ち・バス書込時間分だけ異なります。
別クロックなら長さは4000000/実クロックの比で変わります。
**録音時の実際のOPMクロック設定（4MHz/3.579545MHz等）も教えてください。**
ファイル名を保ったまま、1ファイルにつき1本のWAVで返していただくと対応が確実です。
左右の入替、個別ノーマライズ、編集による途中区間の削除はせず、前回と同じ経路を使用してください。

## 音色とマスクの定義

01/03/04/06はgenerate_mdx.pyのROWSで定義した診断音色を使用。M1/M2が当初提示値と異なっていました。詳細は ../measurements-4mhz/REPORT.md の訂正を参照。
ALG=5、FB=7、全OPキーオン、左右ON、ハードウェア/ソフトウェアLFOなし。
固定音程はKC=48h、KF=0。音名の表記差を避けるため、生のKC値で指定しています。
前回録音と同じ音程だと推定して設定したわけではありません。

ALG5のM1は常に変調器として動作させます。出力を分離する際は、他キャリアのTLを127へ変更。
TL127は約95.25dBの減衰であって、数学的な完全ゼロではありません。
OPのキーを切らないため、マスク解除時に位相・エンベロープを再スタートしません。

02LIVEでは、長い比較中にM1の減衰で変調量が変わることを避けるため、
**M1のD1Rだけ7→0へ変更**した校正音色を使用しています。
01SOLOが診断音色の対照です。02LIVEの変化を診断音色そのままの測定として扱わないでください。
05SINEはALG7/FB0、全OP MUL1/DT1=0/DT2=0/AR31/D1R0/D2R0/TL0の対照音色です。
07LOADは02LIVEと同じM1持続化を使い、他chキャリアにはTL+24（18dB減衰）を加えます。
07LOADの他chは異なるKCで発音。可聴区間は他音も混ざるため、主音の位相をそのまま比較できません。

## 時分割演算をどう切り分けるか

8ch×4OPを発音数に応じて処理量が変わる並列音源として扱わず、
固定の時分割スロットで演算することを前提とした試験構成です。

- 03CHSCANで、同じOPでもチャンネル位置により左右のサンプル対応が変わるかを確認。
- 05SINEで、キャリアの周波数が違うことによる解析誤差を避け、各OPの時間差を比較。
- 02LIVEで、再キーオンによる位相初期化と、出力OPの選別による差を分離。
- 06PAIRで、同じ周波数近傍の成分同士の干渉と左右差の対応を確認。
- 07LOADで、他chのキーオン状態と、出力アキュムレータへ加算される音数の影響を分離。

TLを下げてもOPスロットが処理から取り除かれるわけではありません。
また、このMDXはCPUバスから2クロック単位の任意時刻に書き込む装置ではありません。
同一MDX tick内でもレジスタは順に書かれ、実時間はプレーヤーとBUSY待ちに依存します。
したがって、32スロットの正確な演算順やレジスタ取込エッジをMDXだけで確定することはできません。
主に区間の定常部分を使い、境界付近は書込み過渡として別に評価します。

## MDXの実装方式

FMトラックA〜Hは音符なしで終了。トラックPをレジスタ制御用に使います。
P内にテンポ設定、OPMレジスタ直接書込み、待ち、終了を格納します。
**Pトラックをミュート/スキップしないでください。PCMデータは不要です。**
通常の音符・音色・音量コマンドを使わないので、ドライバのゲート長、音量加算、
キーオン時のTL再書込みやポルタメントがテスト対象へ混ざることを避けています。
プレーヤーがPDXなしのPトラックを読み飛ばしたり、PのOPM書込みを未実装としている場合は
発音しません。その場合は使用プレーヤー名を教えてください。

## 区間の対応

schedule/ のCSVには開始/終了tick、4MHz換算の予定秒数、ch、KC、可聴OPを記載。
traces/ には同じレジスタ列をコアのCLIで再生できる形式で収録。
preview/ の01SOLO.wavと02LIVE.wavは0.7の通常出力で生成した区間確認用です。
実機のステレオ効果を再現した比較基準音ではありません。

## 検証と再生成

- 独自デコーダでMDXとtraceのレジスタ列・時刻が一致することを確認済み。
- 02LIVEのキーオンが先頭の1回だけであることを検査済み。
- traceから01/02のプレビュー音声を生成。実機MXDRV/GMC-OPT04でのMDX再生は未確認。

Python標準ライブラリだけで再生成できます。

```bat
py generate_mdx.py
py verify_mdx.py
```

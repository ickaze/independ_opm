# 周期LFO検証 第3報：25R1〜25R3

2026-09-14。全256周波数設定の測定区間が揃った。今回の追加録音に対して、前回得た候補式を変更せず検証した。

## 収録の確認

|入力|録音全長|基準音から検出した測定区間|対象|
|---|---:|---:|---|
|25R1.flac|740.301146秒|17.780〜737.813秒|06h〜09h|
|25R2.flac|724.665198秒|2.853〜722.864秒|0Ah〜0Dh|
|25R3.flac|375.238906秒|3.534〜363.528秒|0Eh〜0Fh|

いずれも96 kHz/24bitステレオ。測定区間長は予定約720秒、720秒、360秒と整合し、先頭の余白も除外できた。MDX内の各設定の境界は、基準音区間の始点・終点と予定の待ち時間から線形に対応付けた。この対応付けを内部時計の独立検証とは数えない。

これまでの完全区間246設定に残り10設定が加わり、00h〜FFhの256設定すべてに完全区間がある。これはデータの網羅性であり、内部演算が全て確定したという意味ではない。今回の収録不足を補うための追加録音は不要。

## 段差の進み方

各設定から42回、計420回の段差を抽出した。間隔の中央値は06h〜0Fhで約4.193〜4.194秒。前回の00h〜05hと整合する。

追加1段の有無を次の候補で予測した。

    L = LFO FREQの下位4ビット
    extra[n] = reverse4((p+n) mod 16) < L
    increment[n] = 1 + extra[n]

reverse4は4ビットの並びの反転。pは区間ごとの未知の位相。

前回と同じく、各区間の最初の16段だけでp=0..15を選び、残り26段を予測した。

|比較|先頭160段の不一致|保留260段の不一致|
|---|---:|---:|
|単純な小数加算による追加段|28|47|
|4ビット反転カウンタの比較|0|0|

今回の小さい段差の中央値は0.0944014 dB。前回得た0.0944500 dBの1.5倍をしきい値として固定しても、大小分類は420段すべて同一だった。今回の録音に合わせてしきい値を変えなければ合わない結果ではない。

前回の22設定・保留572段と今回の10設定・保留260段を合計すると、00h〜1Fhの32設定で保留832段が不一致0となる。前回の572段は候補を発見した録音内の検証、今回の260段は新しく受け取った録音に対する検証であり、区別して記録する。

この結果は「観測される1段／2段の配列」の検証である。実回路がそのまま4ビット反転カウンタで構成されているとの証明ではなく、他の等価な表現もあり得る。20h〜FFhの追加段配列に対する同じ精度の検証を済ませたという意味でもない。

## 位相を引き継げるか

区間ごとにpを合わせる必要をなくすため、ファイル先頭のpだけを選び、次の区間で42段または43段進める候補も比較した。

|ファイル|42段継承の最小不一致|43段継承の最小不一致|
|---|---:|---:|
|25R1|68|67|
|25R2|26|42|
|25R3|0|4|

これは全データを使って初期pを選ぶ当てはめであり、保留予測ではない。その条件でも25R1・25R2は一致しなかった。従って、この単純な位相継承則は採用しない。

42/43段は今回試した限定的な仮説であり、考えられる全カウンタ構造を否定したものではない。保持中も動く別カウンタ、書き込み時刻との関係などは未同定。区間ごとに録音からpを与えれば合うことを、レジスタ列だけから完全再現できることと混同しない。

## 独立実装に向けた到達点

- 全256設定の収録不足は解消した。
- 00h〜1Fhの定常追加段配列は、既存ソースを期待値に使わず候補式で説明できた。
- 平均周期・波形・深度の前回までの測定表も利用できる。
- 書き込みをまたぐ位相、深度の内部丸め・全端点、深いAM併用時のPM抽出などは残る。

今回、エミュレータ本体とライセンスは変更していない。観測で支持された式と未確定部分を分け、参照由来部分の新規実装・残存確認を経てからライセンスを判断する。録音だけで全参照箇所の置換が完了したとは扱わない。

## 再実行

ZIP最上位を作業ディレクトリとする。今回の3本をupload/に配置する。

    python periodic-completion/extract.py
    python periodic-completion/analyze.py
    python periodic-completion/carry_check.py
    python periodic-completion/bit_reverse_check.py
    python periodic-completion/continuity.py

Python、NumPy、SciPy、ffmpeg/ffprobeを使用。最後の3つは保存済みresults.jsonだけでも再実行できる。元FLACと大きな中間NPZは重複同梱しない。

results.jsonに全段差の時刻と変化量、carry_check_*.jsonに各設定の不一致数、continuity.jsonに不成立だった継承候補を保存した。入力ハッシュはinputs.json。coverage_256.jsonは過去分と今回分を合わせた完全区間の一覧。
